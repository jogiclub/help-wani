# 상담 운영 기능 — 기획서

상담 위젯을 "켜 두기만 하는 채팅창" 에서 **"조직이 언제, 어떻게 응대하는지 고객에게 약속하는 창구"** 로 바꾸는 기능 묶음입니다.
참고 자료(타사 상담 도구 도움말 화면)의 항목을 이 포털 구조에 맞춰 옮겼습니다.

> 참고 이미지 해상도가 낮아 세부 문구는 읽지 못했습니다. 항목 제목과 화면 구성만 참고했고,
> 동작 규칙은 이 포털의 현재 구조(`last_seen_at` 온라인 판별, 오프라인 메일, 첫 응답자 배정)를 기준으로 새로 정했습니다.

---

## 1. 지금 상태와 문제

| 항목 | 현재 | 문제 |
|---|---|---|
| 운영 여부 | 상담원 1명이라도 최근 접속(`last_seen_at`)이면 "온라인" | 밤에 콘솔을 켜 둔 채 퇴근하면 고객은 계속 "상담 가능" 으로 봄 |
| 운영 시간 | 없음 | 고객이 언제 답을 받을 수 있는지 알 수 없음 |
| 부재 안내 | 오프라인 메일(대화당 1회, 조직에게만) | **고객에게는 아무 안내가 없음.** 글을 남기고 무응답으로 느낌 |
| 상담원 상태 | 접속 여부만 | "자리 비움", "점심" 같은 의도적 부재를 표현할 수 없음 |
| 배정 | 먼저 답한 상담원에게 자동 배정 | 두 명이 같은 대화에 동시에 답하는 일이 생김 |
| 새 문의 알림 | 목록 폴링/실시간 갱신뿐 | 다른 탭을 보고 있으면 놓침, 여러 상담원에게 같은 알림이 반복됨 |

## 2. 기능 목록과 우선순위

| # | 기능 | 우선 | 요약 |
|---|---|---|---|
| F1 | 운영 시간 | 1차 | 요일별 운영 시간, 조직 시간대 기준 |
| F2 | 휴일 | 1차 | 특정 날짜 휴무/단축 운영, 국가 공휴일 불러오기 |
| F3 | 운영 상태(수동) | 1차 | 조직 전체 "운영 중 / 운영 종료" 즉시 전환 + 상담원 개인 상태 |
| F4 | 부재중 자동 응답 | 1차 | 운영 시간 외 / 상담원 전원 부재 시 위젯에 자동 메시지 |
| F5 | 위젯 표시 방식 | 1차 | 운영 시간 외 버블 숨김 / 안내만 표시 / 그대로 받기 |
| F6 | 답변 속도 안내 | 2차 | "보통 N분 안에 답변" 표시. 수동 지정 또는 실제 통계 |
| F7 | 중복 응대 방지 | 2차 | 담당자 잠금, 입력 중 표시, 알림 1회화 |
| F8 | 전화 연결 | 2차 | 위젯에 대표 전화 버튼, 운영 시간 외 숨김 |

1차는 "고객에게 운영 시간을 정직하게 보여 주기", 2차는 "상담원끼리 부딪히지 않기" 입니다.

## 3. 기능 상세

### F1. 운영 시간

**설정 위치**: 상담 대화 > 설정 드로어(`_widget_settings.php`)에 `운영 시간` 섹션 추가. 조직 관리자만.

```
운영 시간  [x] 운영 시간 사용        시간대: Asia/Seoul (조직 정보에서 변경)

  월  [x]  09:00 ~ 18:00   [+ 시간대 추가]
  화  [x]  09:00 ~ 18:00
  ...
  토  [ ]  휴무
  일  [ ]  휴무

  점심시간  [x] 12:00 ~ 13:00  (모든 운영일에 적용)
```

규칙

- 시간대는 **조직 시간대(`organizations.timezone`)를 그대로** 씁니다. 따로 고르지 않습니다(3.4 규칙과 일치).
- 하루에 구간을 여러 개 둘 수 있습니다(최대 3개). 자정을 넘는 구간(22:00~02:00)은 **다음 날 구간으로 나눠 저장**합니다.
- "운영 시간 사용" 을 끄면 지금처럼 상담원 접속 여부만으로 판단합니다(기존 조직 동작 유지, 기본값 꺼짐).
- 시각은 분 단위, 저장은 `HH:MM` 로컬 시각입니다. 운영 시간은 "그 조직의 벽시계" 기준이라 UTC 로 바꾸지 않습니다.
  판정할 때만 `now(UTC) -> 조직 시간대` 로 변환해 비교합니다. (서머타임 지역도 이 방식이면 자동으로 맞습니다.)

### F2. 휴일

**설정 위치**: 운영 시간 섹션 아래 `휴일` 목록.

| 칸 | 설명 |
|---|---|
| 날짜 | 하루 또는 기간(시작~끝) |
| 이름 | "추석 연휴", "창립기념일" |
| 방식 | 종일 휴무 / 단축 운영(시간 지정) |
| 매년 반복 | 양력 고정일만(1/1, 12/25 등) |

- [공휴일 불러오기] 버튼: 조직 국가(`organizations.country`)의 올해 공휴일을 목록에 **추가 후보로** 보여 주고 고르게 합니다.
  자동으로 넣지 않습니다(조직마다 쉬는 날이 다름).
  - 공휴일 출처는 구현 전에 정합니다(확인 필요 1). 음력 공휴일 때문에 "매년 반복" 으로는 처리할 수 없습니다.
- 휴일이 운영 시간보다 우선합니다. 단축 운영이면 그날은 휴일에 적힌 시간만 운영합니다.
- 위젯 안내 문구에 휴일 이름을 넣을 수 있습니다: "오늘은 추석 연휴로 쉽니다. 10월 9일 09:00 부터 답변드립니다."

### F3. 운영 상태 — 조직 전체 + 상담원 개인

두 단계로 나눕니다.

**조직 운영 상태**(관리자, 콘솔 상단 스위치)

| 값 | 의미 |
|---|---|
| 자동 | 운영 시간·휴일 설정대로 (기본) |
| 지금 운영 | 운영 시간 밖이어도 받음. **다음 운영 시간 경계에서 자동으로 '자동' 으로 돌아감** |
| 지금 종료 | 운영 시간 안이어도 닫음. 위와 같이 자동 복귀 |

자동 복귀를 두는 이유: 임시로 바꾼 뒤 되돌리는 걸 잊으면 다음 날 하루 종일 닫힌 채로 남습니다.
복귀 시각을 스위치 옆에 표시합니다("18:00 에 자동으로 돌아갑니다").

**상담원 개인 상태**(모든 상담원, 헤더 프로필 옆)

| 값 | 의미 | 온라인 판정 |
|---|---|---|
| 응대 가능 | 기본 | 포함 |
| 자리 비움 | 잠시 부재 | 제외 |
| 응대 종료 | 퇴근 | 제외, 새 문의 알림도 받지 않음 |

- 콘솔 접속이 끊기면(`last_seen_at` 이 `ONLINE_WINDOW_SECONDS` 지남) 상태와 상관없이 제외합니다.
- 로그인하면 "응대 가능" 으로 시작합니다. 마지막 상태를 기억하지 않습니다(어제 "응대 종료" 로 두고 퇴근한 사람이 오늘 안 보이는 문제).

**최종 판정** — 한 곳(`Chat_model::availability($org)`)에서만 계산합니다.

```
운영 중?   = 조직 수동 상태가 있으면 그 값, 없으면 (휴일 아님 AND 운영 시간 안)
응대 가능? = 운영 중 AND (응대 가능 + 최근 접속) 상담원 >= 1

돌려주는 값: { state: 'open' | 'away' | 'closed', reason, next_open_at(UTC) }
  open   운영 중 + 응대 가능 상담원 있음
  away   운영 중이지만 응대 가능 상담원 없음 (모두 자리 비움/미접속)
  closed 운영 시간 외, 휴일, 수동 종료
```

`has_online_agent()` 를 쓰던 곳(위젯 init/poll, 오프라인 메일)은 모두 이 함수로 바꿉니다.

### F4. 부재중 자동 응답

고객이 `away` 또는 `closed` 상태에서 글을 보내면 **시스템 메시지**(`sender_type = 'system'`)를 대화에 넣습니다.

| 상황 | 기본 문구(ko) |
|---|---|
| closed (운영 시간 외) | 지금은 운영 시간이 아닙니다. {next_open} 부터 순서대로 답변드립니다. |
| closed (휴일) | 오늘은 {holiday} 로 쉽니다. {next_open} 부터 답변드립니다. |
| away | 상담원이 잠시 자리를 비웠습니다. 남겨 주시면 곧 답변드립니다. |

- 문구는 조직 관리자가 상황별로 고칠 수 있습니다(빈 값이면 기본 문구). 기본 문구는 세 언어 사전에 넣고(3.2),
  위젯에는 서버가 조직 언어로 만들어 내려줍니다(3.9).
- `{next_open}` 은 조직 시간대로 변환한 시각입니다. 고객 시간대가 다를 수 있으므로 "(한국 시간)" 처럼 시간대 이름을 붙입니다.
- **대화당 상태 구간마다 1번만** 보냅니다. 고객이 연달아 5줄을 써도 자동 응답은 1번입니다.
  상담원이 답하거나 상태가 `open` 으로 바뀌면 다시 보낼 수 있게 됩니다(`conversations.auto_reply_at` 으로 판정).
- 자동 응답도 메시지 저장이므로 **발행을 함께 합니다(3.11).**
- 연락처 받기: `closed` 일 때 이메일을 아직 안 남긴 방문자에게 "답변을 메일로도 받으시겠어요?" 입력 칸을 위젯에 띄웁니다.
  위젯에 이미 있는 프로필 입력을 재사용합니다.
- 기존 오프라인 메일(조직에게 가는 알림)은 그대로 두되, `closed` 일 때는 **운영 시작 시각에 모아서 1통**으로 보내는 옵션을 둡니다(확인 필요 2).

### F5. 위젯 표시 방식

설정: "운영 시간이 아닐 때 위젯을"

| 선택 | 동작 |
|---|---|
| 그대로 표시하고 문의 받기 (기본) | 헤더에 "운영 시간 외 · 내일 09:00 부터 답변" 표시, F4 자동 응답 |
| 안내만 표시 | 대화창은 열리지만 입력칸 대신 운영 시간 표와 전화 번호/가이드 링크 표시. 기존 대화가 있는 방문자는 계속 쓸 수 있음 |
| 숨기기 | 버블 자체를 그리지 않음. 단 **열린 대화가 있는 방문자에게는 표시** (답변을 못 보게 되면 안 됨) |

- 위젯 헤더의 상태 점: `open` 초록 / `away` 노랑 / `closed` 회색.
- 위젯 헤더 아래 한 줄: "운영 시간 평일 09:00-18:00" (요약 문자열은 서버가 만들어 내려줌).
- 상태는 `init` 과 `poll` 응답의 `availability` 로 받습니다. 운영 시간 경계에서 바뀌는 것은 다음 poll 에 반영됩니다(최대 30초 지연, 허용).

### F6. 답변 속도 안내

위젯 헤더에 "보통 **5분 안에** 답변합니다" 를 표시합니다.

| 방식 | 설명 |
|---|---|
| 표시 안 함 (기본) | |
| 직접 지정 | 몇 분 안에 / 몇 시간 안에 / 하루 안에 중 선택 |
| 실제 기록으로 | 최근 7일, **운영 시간 안에 들어온 문의**의 첫 응답 시간 중앙값. 표본 10건 미만이면 표시하지 않음 |

- 첫 응답 시간 = 방문자 첫 메시지 ~ 상담원 첫 메시지. 운영 시간 밖에 들어온 문의는 빼야 숫자가 부풀지 않습니다.
- 계산은 요청마다 하지 않고 1시간마다 조직별로 만들어 둡니다(`organizations.chat_reply_minutes` 캐시 + 갱신 시각).
  크론이 없으면 위젯 init 때 갱신 시각이 1시간 지났을 때만 다시 계산합니다.
- 구간으로 반올림해서 보여줍니다(몇 분 / 10분 / 30분 / 1시간 / 몇 시간). 3분 17초 같은 숫자는 오히려 약속처럼 보입니다.
- `away`, `closed` 일 때는 숨기고 F4 문구를 보여 줍니다.
- 같은 수치를 조직 관리 통계(`/admin`)에 "평균 첫 응답 시간" 으로도 보여 줍니다.

### F7. 중복 응대 방지

지금은 먼저 답한 사람이 담당이 되므로, 두 상담원이 동시에 같은 문의를 열고 답하면 고객이 두 사람에게 답을 받습니다.

1. **담당 표시와 잠금**
   - 대화 목록과 대화창 상단에 "담당: 김상담" 을 크게 표시합니다.
   - 담당자가 있는 대화에 다른 상담원이 보내기를 누르면 확인 모달: "김상담 님이 응대 중입니다. 함께 답할까요? / 담당을 가져올까요?"
   - [담당 가져오기] 는 이전 담당자에게 알림을 주고 `audit_logs` 에 남깁니다.
   - [대기 중으로 돌리기] 버튼으로 담당을 비울 수 있습니다.
2. **보고 있음 / 입력 중 표시**
   - 대화창을 연 상담원과 입력 중인 상담원을 대화창 상단에 표시합니다("이영희 님이 입력 중").
   - realtime-msg 의 `org:{id}` 방에 **휘발성 이벤트**(`viewing`, `typing`)로 보냅니다. 저장하지 않습니다.
     메시지 저장 원칙(3.11)과 충돌하지 않습니다 — 웹소켓으로 받는 것이 아니라 포털 API 로 보낸 것을 포털이 발행만 합니다.
     (realtime-msg 가 클라이언트 발행을 받지 않으므로 `POST /api/console/chat/presence` 로 보내고 포털이 publish 합니다.)
3. **새 문의 알림 1회화**
   - 브라우저 알림(Notification API)과 탭 제목 깜빡임 "(3) 상담 대화" 를 추가합니다. 설정에서 상담원 개인이 끕니다.
   - 같은 대화의 연속 메시지는 **대화당 1번만** 알립니다. 누군가 대화를 열거나 담당이 정해지면 다른 상담원의 알림을 거둡니다.
   - 담당이 있는 대화의 새 메시지는 **담당자에게만** 알립니다.
   - "응대 종료" 상태 상담원에게는 알리지 않습니다.

### F8. 전화 연결

- 위젯 하단에 [전화 상담 02-000-0000] 버튼. 번호는 조직 정보의 대표 전화(`organizations.phone`)를 씁니다(3.13 에서 이미 고객 화면에 노출 중).

## 6. 판정 로직 예시

```

2026-10-08(목) 12:30 KST  -> closed, next_open = 10-08 13:00
2026-10-08(목) 19:00 KST  -> closed, next_open = 10-12(월) 09:00   (금요일 휴일, 주말 건너뜀)

관리자가 10-08 19:00 에 "지금 운영" -> open, chat_manual_until = 10-12 09:00 (자동 판정도 open 이 되는 때)
관리자가 10-08 15:00 에 "지금 종료" -> closed, chat_manual_until = 10-08 18:00 (자동 판정도 closed 가 되는 때)
```

**수동 상태의 복귀 시점**은 "자동 판정이 수동 값과 같아지는 첫 시각" 입니다. 그때 '자동' 으로 돌려도 고객이 보는 상태는 바뀌지 않습니다.
next_open 탐색은 최대 14일 앞까지만 보고, 그 안에 운영일이 없으면 `next_open = null`(문구에서 시각 생략)로 둡니다.

## 8. 확인이 필요한 사항

> 2026-10-21: 1, 3, 4 는 제안대로 진행했습니다(3 은 2차 작업). 2, 5 는 아직 정하지 않았습니다.

1. **공휴일 출처** — (a) 국가별 공휴일을 설정 파일로 매년 직접 갱신 (b) 공공데이터포털 특일정보 API(한국만, 키 필요)
   (c) 외부 공휴일 API. 지원 국가(KR/JP/US?)와 함께 정해야 합니다. 1차는 (a) 한국만을 제안합니다.
2. **운영 시간 외 조직 알림 메일** — 지금처럼 문의마다 즉시(대화당 1회) 보낼지, 운영 시작 시각에 모아서 보낼지.
   모아 보내려면 예약 실행(크론 컨테이너)이 필요합니다. 지금 저장소에는 크론이 없습니다.
3. **"함께 답하기" 허용 여부** — 담당자가 있는 대화에 다른 상담원이 답하는 것을 막을지(잠금), 경고만 할지. 제안은 경고 + 선택.
4. **상담원 개인 상태 노출** — 고객 위젯에 "상담원 2명 응대 중" 처럼 인원을 보여 줄지. 제안은 보여 주지 않음(상태 점만).
5. **요금제 구분** — 운영 시간/자동 응답을 기본 기능으로 둘지, 상위 요금제로 둘지(현재 요금은 단일).
